## 2026-03-12 - [Optimize Backend NLTK and Scikit-learn similarity]
**Learning:** Initializing global data like NLTK stopwords and regex compilation inside request-handling or frequently called functions adds significant overhead (as seen in profiling `get_tokens`). Also, a simple Python loop calculating `cosine_similarity(v1, v2)` individually for many documents creates a large bottleneck when processing lists of items. Scikit-learn's `cosine_similarity` handles matrix operations vector-wise inherently faster.
**Action:** When working with text-processing APIs, extract static data setups (e.g. `STOP_WORDS = set(stopwords.words('english'))`) to the module's global scope. Rather than processing individual pairs in a loop, process arrays/matrices entirely natively via optimized libraries like NumPy/SciPy behind scikit-learn (e.g., `similarities = cosine_similarity(jd_vector, resume_vectors)[0]`).
